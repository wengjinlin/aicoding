## 1. 文档目的

### 1.1 为什么需要这份全景

v3 设计文档已经覆盖了 MCP Adapter 的**核心架构**（声明式工具、智能翻译层、安全边界）和**两块关键治理**（大数据场景、工具生命周期）。但一个长期运行的 MCP 服务还需要**全方位的运营治理**，否则会出现：

- 工具上线后没人监控，AI 调用准确率下降无人发现
- PII 数据泄露事件追溯困难（脱敏规则分散在各 Adapter）
- 多 Adapter 上线后配置漂移、版本不一致
- Token 消耗失控，没有预算管控
- 业务系统故障时 Adapter 无降级策略，雪崩

本全景文档梳理 12 个治理维度，明确每个维度的目标、动作、责任方、度量指标、产出物，作为运营阶段的**清单与路线图**。

### 1.2 与 v3 文档的关系

```
v3 设计文档（架构 + 核心治理）     ← 已完成
        +
MCP 服务治理全景（本文档）          ← 运营清单索引
        ↓
运营手册 Runbook（按维度展开）      ← P0 维度落地后逐步撰写
```

本全景文档**不展开实现细节**，只回答"治理有哪几块、谁来做、做到什么程度"。具体实现由 Runbook 承载。

### 1.3 适用范围

- 所有 Adapter（QMS / MES / WMS / EMS 等）
- 共享库（mcp-common / mcp-auth-filter / mcp-adapter-starter）
- 工具设计师、IT 部、业务部门、AI 平台、合规部门的协作流程

## 15. 落地优先级与路线图

### 15.1 优先级分级

```
P0（v3 落地期就要做，第 1-10 周）
   ├─ D 可观测性：核心指标体系 + 告警
   ├─ A 工具质量：AI 调用准确率监控
   └─ B 安全权限：PII 数据字典 + 服务账号生命周期

   ├─ C 性能稳定：慢调用治理 + 缓存 + 降级
   ├─ G 变更发布：灰度 + 回滚
   ├─ H 资源成本：Token 预算 + 成本归因
   └─ E 工具发现：tools/list 性能 + 工具市场

P2（规模化复制期，第 23 周起）
   ├─ F 数据合规：审计保留 + 个保法 + 跨境
   ├─ I 用户组织：业务对接 + RACI
   ├─ K 业务连续：高可用 + 灾备 + 混沌
   ├─ J 协议生态：协议升级 + 第三方接入
   └─ L 知识文档：术语表 + 培训认证
```
