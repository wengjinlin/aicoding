## 1. 通义灵码（阿里云）

- **母公司**：阿里云（中国，杭州）
- **开源状态**：客户端闭源；模型 Qwen-Coder 部分开源
- **核心能力**：
  - 代码补全 / 智能问答 / 多文件修改 / **编程智能体**
  - 2025 年起深度集成 **魔搭 MCP 广场**（国内最大的 MCP 中文社区）
  - 首创"**自动记忆**"——记住开发者习惯
- **MCP**：✅ **国产工具中最完善**。自动感知 + 调用十多种内置编程工具。
- **社区口碑**：国内第一梯队；Java 场景评测中表现稳定。
- **价格**：个人免费；企业版议价。
- **典型场景**：阿里云生态用户、国内企业、Java 项目。

## 2. CodeBuddy（腾讯云）

- **母公司**：腾讯云（中国，深圳）
- **开源状态**：闭源
- **核心能力**：全流程 AI 开发；与腾讯生态（云开发、CodeStudio）深度集成。
- **MCP**：支持（具体深度待官方文档确认）。
- **社区口碑**：腾讯系项目首选；横向评测中和通义灵码各有胜负。
- **典型场景**：腾讯云用户、微信小程序开发。

## 3. Comate / 文心快码（百度）

- **母公司**：百度（中国，北京）
- **开源状态**：闭源
- **核心能力**：补全 + 问答；强项是中文注释理解。

## 4. Trae（字节跳动）

- **母公司**：字节跳动（中国 / 新加坡）
- **开源状态**：闭源
- **核心能力**：
  - 国内最强"Cursor 替代品"——VS Code fork
  - 海外版可调用 Claude；国内版调用豆包
  - 免费 + 订阅双轨
- **MCP**：✅ 支持。
- **社区口碑**：免费策略激进，国内独立开发者用得多。
- **典型场景**：想体验 Cursor 但不想付费的开发者。

## 5. CodeGeeX（智谱 AI）

- **母公司**：智谱 AI（中国，北京；清华系）
- **开源状态**：✅ **模型开源**（CodeGeeX4 系列在 Hugging Face 开放）；客户端免费
- **核心能力**：
  - 补全 + 问答 + 智能体
  - 模型可本地部署（开源版本）
- **MCP**：✅ 支持。
- **社区口碑**：清华系学术 + 工程结合，社区贡献活跃；国际开源社区有一定认知度。
- **典型场景**：想本地部署模型的研究者 / 国企 / 高校。

- **母公司**：字节跳动
- **核心能力**：免费 + 云 IDE；和 Trae 同公司但定位更"轻量"。
- **MCP**：✅ 支持。

## 7. DeepSeek-Coder（深度求索）

- **母公司**：深度求索（中国，杭州）
- **核心定位**：**这是模型，不是工具**——但通过 OpenAI-compatible API 可被任何工具（Aider / Cline / Continue）调用。
- **价格**：**API 极便宜**，是 2025 年开源阵营的"性价比之王"。
- **社区口碑**：开源模型中国际声誉最高。Aider 排行榜上长期高分。
- **典型场景**：BYOK + 预算敏感 + 开源。

---

## 8. Kimi Code CLI（月之暗面）⭐

- **母公司**：月之暗面 / Moonshot AI（中国，北京）
- **开源状态**：✅ 部分开源（2025 年 1024 程序员节开源 Kimi CLI；2026 年初发布 Kimi Code 0.4.0）
- **形态**：**独立 CLI**（macOS / Linux），TypeScript 重写
- **核心能力**：
  - 基于 **Kimi K2 → K2.5 → K2.6** 模型
  - **200 万汉字上下文**——业界最长
  - **K2.6 模型**号称可"不间断编码 13 小时、单次修改 4000+ 行"
- **MCP**：✅ 支持
- **BYOK**：✅ 支持 API Key + Kimi 会员双通道
- **社区口碑**：K2.6 模型在开源社区评价高；国产 CLI 阵营代表
- **典型场景**：长上下文 + 国产 BYOK + 命令行重度用户

## 9. Qwen Code CLI（阿里通义）⭐

- **母公司**：阿里通义（中国，杭州）
- **开源状态**：✅ 开源
- **形态**：**独立 CLI**——**基于 Gemini CLI 二次开发**
- **核心能力**：
  - 针对 **Qwen3-Coder**（480B 参数、1M token 上下文）优化
  - 增强了解析器与工具调用协议
  - 支持 agentic coding
- **MCP**：✅ 支持
- **接入方式**：阿里云百炼按量计费 / Coding Plan / Token Plan
- **社区口碑**：阿里云用户首选 CLI；Qwen3-Coder 在 Aider 排行榜居前列
- **典型场景**：阿里云生态 + Qwen3-Coder 偏好 + 命令行

## 10. 国产工具的"双形态"现状

值得专门指出：**国产工具正分化为两条路线**——

| 路线 | 代表 | 特征 |
|------|------|------|
| **A. IDE 插件 / Fork 路线** | 通义灵码、CodeBuddy、Comate、Trae、MarsCode | 模仿 Cursor/Windsurf，重 UI、轻脚本化 |
| **B. CLI 原生路线** | Kimi Code、Qwen Code | 模仿 Claude Code，重 Agent 工作流、轻 UI |

此前国产阵营几乎全是 A 路线；2025 年下半年起 Kimi Code、Qwen Code 等 B 路线产品崛起，**国产 CLI 第一次有了和 Claude Code/Aider 同台竞争的形态**。这是重要的趋势变化。

## 国产工具的整体特征

### ✅ 优势

1. **中文场景适配**——中文注释、中文文档、中国业务术语理解远好于海外工具
2. **本地化合规**——满足等保 / 数据出境要求；企业版可私有部署
3. **价格激进**——大部分个人版免费，海外工具 $15–20/月对比鲜明
4. **生态集成**——通义接阿里云、CodeBuddy 接腾讯云、Comate 接百度智能云

### ⚠️ 局限

1. **国际影响力弱**——除 DeepSeek-Coder、CodeGeeX 外，大部分国产工具国际社区认知度低
2. **模型默认绑定**——大部分绑定自家模型，BYOK 受限
3. **第三方评测缺失**——SWE-bench 等权威榜单上少有国产工具身影（GLM-5/Qwen-Coder 模型本身除外）
4. **海外可用性参差**——Trae、CodeGeeX 部分功能海外可用，其他多限于中国大陆

### Harness V2 视角的提示

Harness V2 基础设施层完全**模型无关、工具无关**。国产工具的接入方式：

| 工具 | 接入 Harness 的方式 |
|------|-------------------|
| 通义灵码 / CodeBuddy / Trae | 通过 MCP 客户端调用 Harness 提供的 MCP 服务（如 OMC、guard hooks） |
| DeepSeek-Coder / Qwen-Coder | 作为 BYOK 模型，喂给 Claude Code / Aider / Cline |
| CodeGeeX | 模型可本地部署 → Ollama → 任意 BYOK CLI |
